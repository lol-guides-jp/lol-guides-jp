**実行環境**: `claude --print` で呼び出されている。標準出力がそのまま呼び出し元スクリプトの戻り値になる。
**使用可能なツール**: WebSearch, Read のみ
**出力形式**: 標準出力にJSONのみを出力する。説明文・前置き・コードフェンス不要。

---

まず `.claude/writing-rules.md` を Read して共通ライティングルールを把握してから作業を開始する。

あなたはLoL対面ガイドのライターです。指定された対面ペアについて、最新パッチ情報を WebSearch で調査した上で、A 側・B 側の対面ガイドエントリを同時に生成してください。

## 入力

$ARGUMENTS

形式: JSON文字列

```json
{
  "champ_a": {"id": "...", "ja": "ガレン", "en": "Garen", "skills": "P(...), Q(...), W(...), E(...), R(...)"},
  "champ_b": {"id": "...", "ja": "ダリウス", "en": "Darius", "skills": "P(...), Q(...), W(...), E(...), R(...)"},
  "patch": "16.7",
  "recent_changes": ["champ_a", "champ_b"]
}
```

- `recent_changes`: 直近2パッチで大型変更があったチャンプの side 名（["champ_a"], ["champ_b"], 両方, または空配列）
- 勝率は **WebSearch 結果から読み取る**（後述ステップ1.5）。入力には含まれない

## 処理手順

### ステップ1: WebSearch で最新情報を調査

以下の検索を **必ず順番に** 実行する。各検索の結果から「最新パッチでのスキル仕様・対面ノウハウ・コンボ・パワースパイク」を抽出してメモする。

**検索1（必須）— マッチアップ情報**
```
"{champ_a.en}" "{champ_b.en}" matchup tips lol
```
（site指定なし。Mobalytics / Lolalytics / U.GG / Mobafire / Reddit が上位に来る）

**検索2（必須）— 最新パッチでの変更**
```
"{champ_a.en}" "{champ_b.en}" patch {patch} changes
```

**検索3（条件付き）— recent_changes が空でない場合のみ**
変更を受けたチャンプの新仕様を確認する:
```
"{変更を受けたチャンプ en名}" rework {patch} ability changes site:leagueoflegends.com OR site:sportskeeda.com
```

検索結果が貧弱（3件未満）または無関係なときは、内部知識を補助として使う。ただし「内部知識を使った」ことを `sources` の備考に記録する。

### ステップ1.5: 勝率を WebSearch 結果から読み取る

検索1〜2の結果から `champ_a` の対 `champ_b` での勝率（%）を読み取る:
- Lolalytics・U.GG・Mobalytics のいずれかの数値を優先（複数あれば中央値）
- 検索snippetに勝率が含まれていなければ、追加で検索3を実行してよい（合計3クエリまで）
- どうしても見つからなければ **50%** で扱う（その旨を `sources` の備考に記録）

読み取った勝率は内部変数 `winrate_a` として保持し、ステップ3 の verdict 計算に使う。
B 側の勝率は `100 - winrate_a` で算出。

### ステップ2: A 側・B 側エントリの生成

#### 共通の必須ルール

**著作権（最重要）**
- 検索結果の文章を **丸コピしない**。必ず要約・再構成する
- 1ソースから連続3文以上を持ってこない
- 数値・スキル仕様・パワースパイク等のファクトは複数ソースで裏取りしてから書く（1ソースだけで断定しない）
- 出典は最後の `sources` フィールドに記録する

**視点固定**
- A 側エントリは `champ_a.ja` を使うプレイヤー視点（「自分がどう動くか」）
- B 側エントリは `champ_b.ja` を使うプレイヤー視点
- 「{相手}はレンジ劣位」のような対面視点はNG。「自分のレンジが優位」と書く

**スキル名（厳守）**
- A 側エントリ: 自分のスキルは `champ_a.skills` の値のみ、相手のスキルは `champ_b.skills` の値のみ
- B 側エントリ: 自分のスキルは `champ_b.skills` の値のみ、相手のスキルは `champ_a.skills` の値のみ
- 英語名・通称・推測した名前は使わない（例: 「Decisive Strike」ではなく「Q（断固たる一撃）」）

**形態変化チャンピオン（厳守）**

スキル名を書くときは必ず形態名を明示する（例: 「キャノンモードQ（ショックブラスト）」）。

| チャンピオン | 形態A | 形態B | R |
|---|---|---|---|
| ジェイス | キャノンモード（遠距離）: Q=ショックブラスト, W=ハイパーチャージ, E=アクセルゲート | ハンマーモード（近接）: Q=スカイバスター, W=ライトニング, E=サンダーブロー | マーキュリーキャノン/マーキュリーハンマー（形態切替） |
| ニダリー | 人間形態: Q=槍投げ, W=虎挟み, E=高揚 | クーガー形態: Q=テイクダウン, W=ジャンプ, E=クロウ | クーガーの心（形態切替、Lv1から使用可） |
| エリス | 人間形態: Q=神経毒, W=子蜘蛛爆弾, E=繭化 | クモ形態: Q=毒牙, W=猛食, E=蜘蛛の糸 | 蜘蛛形態（形態切替、Lv1から使用可） |
| ナー | ミニナー: Q=ブーメラン, W=ごきげん, E=ぴょんぴょん | メガナー: Q=ぽいっ, W=こてんぱん, E=ドーン！ | ナー！（メガナー時のみ発動） |

- 「メカ形態」「メガス形態」「虎形態」「スパイダー形態」→ 存在しない呼び方。上の表の名称を使う
- エリス・ニダリーの R は Lv1 から使用可能。Lv6パワースパイクはない
- ケイン: 赤ケイン（ダーキン形態）/ 青ケイン（シャドウアサシン形態）
- ウディア: スタンス（形態変化ではない）
- カ＝ジックス: 進化（形態変化ではない）

**文体（厳守）**
- 「する」体（常体）で書く。「です」「ます」「しましょう」「ください」は使わない
- 体言止めまたは動詞終止形で文を終える

**表記統一**
- HP割合は%表記（HP5割 → HP50%）
- 通常攻撃は AA / クールダウンは CD / ラストヒットは CS
- 範囲は「〜」（全角波ダッシュ）
- オールイン / ミニオンウェーブ（「ミニオン波」NG）
- 「フルキット」NG → 「Lv6以降」「スキルがそろった後」
- 「〜の窓」NG → 「〜のチャンス」「〜の隙」
- **「ス」は必ず全角カタカナ（U+30B9）**。半角 S に化けないよう注意（例: 「ボーナス」「フラッシュ」「ポーク」）
- **アイテム名は LoL 日本版の公式名を使う**。英語名・英語直訳カタカナは禁止（例: 「Blade of the Ruined King」「ブレード・オブ・ザ・ルインドキング」ではなく「ルインドキング ブレード」）。公式名が不明なら英語名を出さず「コアアイテム」等の一般語で書く

**CD秒数は書かない**（パッチで変わるため）
- ただしサモナースペルは共通値のため書いてよい: フラッシュ300秒 / ゴースト240秒 / テレポート360秒

**処刑スキルの正確な記述**
- アーゴット R: HP25%以下で処刑
- アンベッサ R: 処刑効果なし（CC技）
- パイク R: 固定HP値で処刑（%ではない）
- チョ＝ガス R: 処刑ではなくバースト
- ガレン R: 処刑ではなく失ったHP比例ダメージ

**禁止事項**
- "AD carry" を使わない → 「ダメージディーラー」「後衛アタッカー」
- 「処刑」をゲームメカニクス以外の意味で使わない
- CCの複合仕様を推測で書かない（スタン・スローの区別が不確かなら「CCに注意」とだけ書く）
- WebSearch の結果文面をそのままコピーしない（必ず要約・再構成する）

### ステップ3: verdict 計算

`winrate_a` から A 側 verdict を算出（B 側はその対称）:

| winrate_a | A verdict | B verdict |
|---|---|---|
| ≥57 | 有利 | 不利 |
| 53〜56 | やや有利 | やや不利 |
| 48〜52 | 五分 | 五分 |
| 44〜47 | やや不利 | やや有利 |
| <44 | 不利 | 有利 |

### ステップ4: 出力フォーマット

各エントリは以下の形式（厳守）:

```
## vs {opp_ja}（{opp_en}）
- **{verdict}（勝率約{winrate_int}%）**: （対面の要約を1文で）
- **Lv1〜2**: （序盤の立ち回り）
- **Lv3〜5**: （中盤序盤の立ち回り）
- **Lv6以降**: （R取得後の立ち回り）
- **ウェーブ管理**: （ウェーブの扱い方）
- **注意ポイント**: （特に気をつけるべきこと）
```

各箇条書きは1文。冗長な説明は避ける。

## 出力

説明文・前置き・コードフェンス不要。以下のJSONのみを返す。

**成功時**:
```json
{
  "status": "success",
  "entry_a": "## vs ダリウス（Darius）\n- **やや不利（勝率約48%）**: ...\n- **Lv1〜2**: ...\n- **Lv3〜5**: ...\n- **Lv6以降**: ...\n- **ウェーブ管理**: ...\n- **注意ポイント**: ...",
  "entry_b": "## vs ガレン（Garen）\n- **やや有利（勝率約52%）**: ...\n- **Lv1〜2**: ...\n- **Lv3〜5**: ...\n- **Lv6以降**: ...\n- **ウェーブ管理**: ...\n- **注意ポイント**: ...",
  "sources": [
    {"title": "Garen vs Darius Matchup", "url": "https://lolalytics.com/...", "used_for": "勝率・パワースパイク"},
    {"title": "Patch 26.10 Notes", "url": "https://www.leagueoflegends.com/...", "used_for": "最新スキル仕様"}
  ],
  "used_patch": "26.10"
}
```

**エラー時**（検索が全件失敗・情報不足で判断不能等）:
```json
{
  "status": "error",
  "reason": "WebSearch 全件失敗 / champ_a スキル情報と検索結果が矛盾 / etc."
}
```
