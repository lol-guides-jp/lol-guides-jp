**実行環境**: `claude --print` で呼び出されている。標準出力がそのまま呼び出し元スクリプトの戻り値になる。
**使用可能なツール**: WebSearch, Read のみ
**出力形式**: 標準出力に以下のJSONオブジェクトのみを出力する。説明文・前置き・コードフェンス不要。

---

あなたは LoL のチャンピオン pick 傾向を分析するアナリストです。
指定された全チャンピオンについて、メインロール・サブロールを判定してください。

## 入力

$ARGUMENTS

形式: JSON文字列

```json
{
  "champions": [
    {"id": "pyke", "ja": "パイク", "en": "Pyke"},
    {"id": "sett", "ja": "セット", "en": "Sett"},
    ...
  ],
  "patch": "26.10"
}
```

## サブロール定義（重要）

**「そのチャンプ全 pick の 15% 以上が、そのロールで pick されている」場合、そのロールを `sub` に含める。**

- 例: Pyke が全 pick の 80% サポート + 18% ミッド + 2% その他 → main=["サポート"], sub=["ミッドレーン"]
- メインロールが複数（両方50%程度）の場合は main に複数記載（例: Senna ADC + サポート）
- 15% 未満のロールは含めない（ノイズ除外）

## 処理手順

### ステップ1: WebSearch で最新メタを確認（**最大3回まで**）

**検索1（必須）— 最新パッチのロール分布傾向**
```
LoL patch {patch} champion role distribution meta tier list
```

**検索2-3（任意）— 知識が古そうな新チャンプ・大型変更があったチャンプの確認**
- 2026年以降に追加されたチャンプ
- 直近のリワークで role が変わったチャンプ

### ステップ2: 全チャンプの判定

入力の `champions` 配列の全エントリについて、以下のルールで判定:

1. **メインロール（main）**:
   - 最も pick rate が高いロールを必ず含める
   - 2番目のロールも pick rate が 35% 以上なら main に含める（両方メイン級）

2. **サブロール（sub）**:
   - pick rate が 15% 以上 35% 未満 のロールを含める
   - main に含めたロールは sub に含めない
   - 該当ロールがなければ空配列 `[]`

3. **ロール名の表記**（必ずこの表記を使う）:
   - `トップレーン` / `ジャングル` / `ミッドレーン` / `ADC` / `サポート`

### ステップ3: JSON 出力

以下の形式で標準出力に出力する。

```json
{
  "_generated": "2026-05-25T10:00:00Z",
  "_patch": "26.10",
  "champions": {
    "pyke": {
      "ja": "パイク",
      "en": "Pyke",
      "main": ["サポート"],
      "sub": ["ミッドレーン"]
    },
    "sett": {
      "ja": "セット",
      "en": "Sett",
      "main": ["トップレーン"],
      "sub": ["サポート"]
    },
    "garen": {
      "ja": "ガレン",
      "en": "Garen",
      "main": ["トップレーン"],
      "sub": []
    }
  }
}
```

**必ず**:
- `_generated` は ISO8601 形式の現在時刻（UTC）
- `_patch` は入力 patch を埋める
- 入力の全チャンプを `champions` に含める（sub が空でも main は必ず1つ以上）
- ロール名は上記5種類のみ（表記揺れ厳禁）
- JSON以外の出力（前置き・コードフェンス・説明文）を絶対に出さない
