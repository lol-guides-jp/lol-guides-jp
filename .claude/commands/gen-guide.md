**実行環境**: `claude --print` で呼び出されている。標準出力がそのまま呼び出し元スクリプトの戻り値になる。
**使用可能なツール**: WebSearch, Read のみ
**出力形式**: 標準出力にJSONのみを出力する。説明文・前置き・コードフェンス不要。

---

まず `.claude/writing-rules.md` を Read して共通ライティングルールを把握してから作業を開始する。

あなたはLoLチャンピオンガイドのライターです。**新規追加されたチャンピオン**について、最新パッチ情報を WebSearch で調査した上で、`guide.md`（チャンピオン単体の立ち回りガイド）を1本生成してください。

## 入力

$ARGUMENTS

形式: JSON文字列

```json
{
  "id": "yunara",
  "ja": "ユナラ",
  "en": "Yunara",
  "skills": "P(誓い〜), Q(〜), W(〜), E(〜), R(〜)",
  "patch": "26.11"
}
```

- `skills`: Data Dragon ja_JP から取得した正式スキル名と説明。**スキル名はこの値のみを使う**（英語名・推測名は禁止）
- `id` はディレクトリ名（小文字 slug）。出力ファイルパスの決定に使う（このコマンドはファイル書き込みはしない。本文だけ返す）

## 処理手順

### ステップ1: WebSearch で最新情報を調査

以下を **順番に** 実行し、各結果から「主流レーン・スキルオーダー・パワースパイク・ゲームプラン・対策」を抽出してメモする。

**検索1（必須）— 主流ロールとビルド**
```
"{en}" lol best role build guide patch {patch}
```

**検索2（必須）— スキル詳細とパワースパイク**
```
"{en}" lol abilities skill order power spike
```

**検索3（必須）— 立ち回り・対面の注意点**
```
"{en}" lol how to play tips counters
```

検索結果が貧弱（合計3件未満）または無関係なときは内部知識を補助として使う。その旨を `sources` の備考に記録する。

### ステップ1.5: 主流ロール（レーン）を判定する

検索結果から、現環境で **最も主流のレーン** を1つ判定する。返す値は次のいずれか（厳守。表記を変えない）:

- `トップレーン`
- `ジャングル`
- `ミッドレーン`
- `ADC`（ボットのマークスマン枠。「ボットレーン」とは書かない）
- `サポート`

複数レーンで使われる場合は **prピック率/勝率が最も高いメイン** を選ぶ。判定根拠を `sources` の備考に1行残す。

### ステップ2: guide.md 本文の生成

`.claude/writing-rules.md` の全ルールに従う。既存ガイドと同じ構成・密度で書く。文体は「する」体（常体）。**「ス」は必ず全角カタカナ（U+30B9）**。

各セクションの中身:

- **一言まとめ**: チャンピオンの立ち位置を1〜2文で
- **スキルオーダー**: `推奨: R > ? > ? > ?` の1行 + 「→ 理由1行」
- **主要パワースパイク**: Lv別とコア換算で3〜4項目（`- **Lv3**: ...` 形式）。アイテムはコア数主軸、現パッチ主力を括弧補足（日本語正式名のみ）。CD秒数は書かない
- **ゲームプラン**: 序盤（〜15分）/ 中盤（15〜25分）/ 終盤（25分〜）の3フェーズ。各2〜3文
- **集団戦の立ち回り**: 役割 / ポジション / 優先ターゲット / コンボ・意識すること の4項目（`- **役割**: ...` 形式）
- **得意マッチアップ** / **苦手マッチアップ**: 各2〜3体。`- **相手名**: 理由1文` 形式。確証が薄ければ無理に埋めず1〜2体でよい（後段の対面ガイド生成で育つ）
- **対策（敵チームに{ja}がいる場合）**: 相手にしたときの対策を3〜4項目（`- **見出し**: ...` 形式）

### 著作権（最重要）

- 検索結果の文章を丸コピしない。必ず要約・再構成する
- 1ソースから連続3文以上を持ってこない
- 数値・スキル仕様・パワースパイクは複数ソースで裏取りしてから書く

### スキル名（厳守）

- 自分のスキルは入力 `skills` の値のみを使う。英語名・通称・推測名は禁止（例: 「Q（栽培の精霊）」のように日本語正式名で書く）
- 形態変化チャンピオン（ジェイス/ニダリー/エリス/ナー等）は形態名を明示する

## 出力フォーマット

説明文・前置き・コードフェンス不要。以下のJSONのみを返す。

**成功時**:
```json
{
  "status": "success",
  "role": "ADC",
  "guide_md": "# Yunara（ユナラ）ADC パッチ26.11\n\n## 一言まとめ\n...\n\n## スキルオーダー\n...\n\n## 主要パワースパイク\n...\n\n## ゲームプラン\n...\n\n## 集団戦の立ち回り\n...\n\n## 得意マッチアップ\n...\n\n## 苦手マッチアップ\n...\n\n## 対策（敵チームにユナラがいる場合）\n...\n\n---\n\n*パッチ26.11 対応 / 参照: [Mobalytics](https://mobalytics.gg/lol/champions/yunara/guide)*",
  "sources": [
    {"title": "Yunara Build Guide", "url": "https://...", "used_for": "主流ロール・スキルオーダー"},
    {"title": "Patch 26.11 Notes", "url": "https://...", "used_for": "最新仕様"}
  ],
  "used_patch": "26.11"
}
```

- `guide_md` は **タイトル行（`# {en}（{ja}）{role} パッチ{patch}`）から末尾の出典行まで** を含む完全な Markdown。タイトル行の `{role}` はステップ1.5 で判定した値と一致させる
- 末尾の参照リンクの `{id}` 部分（Mobalytics URL）は入力の `id` を使う

**エラー時**（検索全件失敗・情報不足で判断不能等）:
```json
{
  "status": "error",
  "reason": "WebSearch 全件失敗 / スキル情報と検索結果が矛盾 / etc."
}
```
